# 出海私域：用户场景细化与系统功能映射

> 承接 [`2026-04-28-outbound-private-domain-localization-design.md`](./2026-04-28-outbound-private-domain-localization-design.md) 中 agents 讨论结论，将 Epic **E1–E6** 落实为 **可评审的用户场景** 与 **系统功能清单**。  
> **说明**：下列「系统」指 Open SCRM 目标形态；标注 **【现有】** 的表示仓库 S1–S6 已有近似能力，出海期多为 **扩展字段或复用**；未标注为 **【新增/扩展】**。

---

## 1. 功能总览（能力编号）

便于评审与排期，每条用户场景末尾标注能力编号。

| 编号 | 能力名称 | 关联 Epic | 简述 |
|------|-----------|-----------|------|
| **REG-01** | RegionPack 配置与版本 | E1 | 国家/城市默认触点、时区、节庆钩子、支付提示、禁忌词分区 |
| **REG-02** | 租户默认区域与合规模式 | E1/E2 | 绑定 `default_region_pack_id`、`compliance_profile` |
| **CON-01** | 同意采集入口（订阅/勾选） | E2 | 落地页、OA、表单回写 → 写入 ledger |
| **CON-02** | Consent Ledger 只增审计链 | E2 | 目的、策略版本、时间、渠道、locale |
| **CON-03** | 按目的评估「是否可触达」 | E2 | 发送前拦截；与营销队列联动 |
| **CON-04** | 撤回同意与全局退订 | E2 | 停止营销类自动化与画像用途（可配置保留合同数据） |
| **CH-01** | 渠道适配器 + Mock 通道 | E3 | WeCom / WABA / LINE / Messenger 统一发送接口 |
| **MSG-01** | 发送载荷扩展 | E3/E4 | `regionPackId`、`consentPurpose`、幂等 【现有扩展】 |
| **ORCH-01** | 人群分群与圈选 | E4 | 标签、来源、Region 组合 |
| **ORCH-02** | 触达计划与频次上限 | E4 | 排期、冷却时间、按区域时区发送 |
| **ORCH-03** | SOP 阶段模板 | E4 | 拉新→培育→转化节点与准入条件 |
| **LOC-01** | 多语言素材与变量 | E4/E1 | 模板 `th-TH` / `de-DE` 等 |
| **LOC-02** | 禁忌词与敏感规则 | E1 | 发送前扫描 / 拦截 / 告警 |
| **ANA-01** | UTM / 活动归因字段 | E6 | 从落地到联系人、到消息日志 |
| **ANA-02** | 漏斗与矩阵健康看板 | E6 | 同意率、24h 对话率、封禁/投诉占位 |
| **AI-01** | 多语种话术草稿（人审） | E5 | 坐席点选后发送；审计日志 |
| **AI-02** | 会话摘要与标签建议态 | E5 | 确认后写入正式标签 |
| **AI-03** | 意图/优先级建议（可解释） | E5 | 引用原文片段；主管覆盖 |
| **AI-04** | AI 披露与关闭个性化 | E5/E2 | 自动回复标注；关闭后中性排序 |
| **SLA-01** | SLA 与升级规则（配置） | E4/E6 | 队列、超时升级；可与现有客服流程迭代 |

## 2. 用户场景格式说明

每条场景均包含：

- **场景编号**：`US-OUT-xxx`
- **谁用**：主角色 + 可选协同角色
- **目标**：业务结果
- **怎么用**：用户与系统交互步骤（用户动作 **加粗**，系统响应 `代码块样式` 用行内描述）
- **系统做什么**：系统侧能力摘要
- **能力映射**：上表编号

## 3. 跨区域通用场景（方法论 / 组织）

### US-OUT-001 按国家管理 IM 矩阵与权限

| 字段 | 内容 |
|------|------|
| **谁用** | 出海运营负责人；协同：IT 管理员（账号密钥） |
| **目标** | 多市场多账号分工清晰、降低误发与封号风险 |
| **怎么用** | 1）**运营**在后台「矩阵管理」新建分组（如 SEA-泰国、EU-德国）。 2）**运营**为分组绑定 **RegionPack**（时区、默认渠道类型）。 3）**运营**添加渠道账号（LINE OA ID / WABA 号占位），**IT** 录入 BSP 凭据至密钥域。 4）**系统**校验凭据格式与租户隔离，返回账号健康状态（连接中/未配置）。 5）**运营**为坐席分配「可操作的账号子集」与角色权限。 |
| **系统做什么** | 持久化矩阵元数据；RBAC 控制可见渠道；审计「谁绑定了哪个号」。 |
| **能力映射** | REG-01, REG-02, CH-01 |

### US-OUT-002 分层人群进入不同 SOP

| 字段 | 内容 |
|------|------|
| **谁用** | 私域操盘手 |
| **目标** | 新客 / 沉默 / 高价值不同培育节奏，且控制频次 |
| **怎么用** | 1）**操盘手**定义规则：例如「来源=TikTok 且 7 日无下单 → 沉默组」。 2）**系统**按规则 nightly 或实时刷新分群成员。 3）**操盘手**为每组绑定 **SOP 模板**（欢迎→教育→首单提醒）。 4）**操盘手**设置该组 **频次上限**（如每用户每周 ≤2 条营销）。 5）**系统**在排期发送前计算冷却，超限则跳过并记原因。 |
| **系统做什么** | 分群计算、SOP 状态机、与发送队列集成；拒绝时写审计。 |
| **能力映射** | ORCH-01, ORCH-02, ORCH-03, CON-03, MSG-01 |

### US-OUT-003 维护多语言素材与禁忌词

| 字段 | 内容 |
|------|------|
| **谁用** | 本地化/内容运营 |
| **目标** | 一线发出一致话术，降低宗教/法律类事故 |
| **怎么用** | 1）**运营**在「素材库」按 `locale` 上传文案与变量（如 `{{price_thb}}`）。 2）**运营**在「禁忌词库」选择 RegionPack 分区，导入词表。 3）**坐席**发送前 **系统** 自动扫描命中则拦截或降级为人工复核队列。 |
| **系统做什么** | 模板版本化；命中规则可配置为拦截/警告；记录命中日志。 |
| **能力映射** | LOC-01, LOC-02, REG-01 |

### US-OUT-004 广告到私域全链路归因

| 字段 | 内容 |
|------|------|
| **谁用** | 增长负责人；协同：数据分析师 |
| **目标** | 看清 UTM → 加好友/关注 → 会话 → 成交 |
| **怎么用** | 1）**增长**在广告后台配置 UTM。 2）**增长**在落地页或 OA 链接携带 `utm_*` 与内部 `campaign_id`。 3）用户完成「关注/留资」时 **系统** 将 UTM 与联系人主档合并。 4）**分析师**在看板选择活动，查看「曝光→关注→首条消息→订单（或手工标记转化）」漏斗。 |
| **系统做什么** | 归因字段标准化存储；与 `message_log` / 联系人时间线关联；看板查询。 |
| **能力映射** | ANA-01, ANA-02 |

### US-OUT-005 配置 SLA 与升级，避免高价值漏跟

| 字段 | 内容 |
|------|------|
| **谁用** | 客服主管 |
| **目标** | 高意向/高客单客户在 SLA 内被响应或升级 |
| **怎么用** | 1）**主管**定义队列（如「泰语售前」）与首响 SLA（如 15 分钟）。 2）**系统**监听渠道进线或会话事件，超时未认领则 **升级** 到组长并通知。 3）**主管**复盘超时原因，调整人力排班（与 Region 时区挂钩）。 |
| **系统做什么** | SLA 计时、升级策略、通知渠道（站内/邮件占位）；与渠道进线事件源对接（依赖 CH-01）。 |
| **能力映射** | SLA-01, REG-02（时区）, CH-01 |

## 4. 泰国 / 曼谷锚点场景（增长与触点）

### US-OUT-TH-001 节庆排期触达（LINE OA 心智）

| 字段 | 内容 |
|------|------|
| **谁用** | 区域运营负责人 |
| **目标** | 宋干/水灯等节点自动/半自动发券与提醒，且可监控屏蔽率 |
| **怎么用** | 1）**运营**在「营销日历」选择 RegionPack `th-bangkok`，勾选预设节庆模板。 2）**系统**按 **Asia/Bangkok** 时区生成排期任务。 3）**运营**圈选人群并绑定泰语券模板。 4）**系统**在发送前跑 **禁忌词** 与 **频次上限**。 5）**运营**在看板查看送达、打开、屏蔽率（字段依赖渠道回执，无则占位）。 |
| **系统做什么** | RegionPack 节庆钩子 + ORCH 排期 + LOC + CON-03；经 CH-01 下发 LINE（或 Mock）。 |
| **能力映射** | REG-01, ORCH-02, LOC-01, LOC-02, CON-03, CH-01, ANA-02 |

### US-OUT-TH-002 TikTok 落地导流 LINE OA 与 A/B 首屏

| 字段 | 内容 |
|------|------|
| **谁用** | 增长负责人 |
| **目标** | 对比不同泰语利益点与泰铢标价对「关注→首单」的影响 |
| **怎么用** | 1）**增长**创建两个落地页变体 A/B，均带不同 `utm_content`。 2）用户点击后跳转 **LINE OA 关注链接**（带追踪参数）。 3）**系统**将关注事件与 UTM 写入联系人。 4）**增长**在报表对比两路转化率。 |
| **系统做什么** | 短链/参数保留；归因写入；漏斗展示。 |
| **能力映射** | ANA-01, REG-01（默认 OA 链接模板）, CH-01 |

### US-OUT-TH-003 双语话术库与曼谷时区排班

| 字段 | 内容 |
|------|------|
| **谁用** | 客服负责人；协同：排班管理员 |
| **目标** | 泰/英脚本一致；高峰对齐本地时间 |
| **怎么用** | 1）**客服**在素材库维护「泰」「英」平行话术。 2）**排班**设置坐席可用时段为 UTC+7。 3）**系统**在 UTC+7 外将进线路由到「异步工单」或「外包队列」（可配置）。 |
| **系统做什么** |  locale 维度素材；排班与路由表；与 SLA-01 联动。 |
| **能力映射** | LOC-01, REG-02, SLA-01 |

### US-OUT-TH-004 门店与线上一致权益（纠纷减损）

| 字段 | 内容 |
|------|------|
| **谁用** | 区域负责人 |
| **目标** | 私域券与门店核销规则一致，减少 COD/地址纠纷 |
| **怎么用** | 1）**负责人**在后台配置券规则：适用门店列表、是否支持 COD。 2）**系统**在发券模板中注入 **支付提示**（来自 RegionPack `paymentHints`）。 3）用户到店核销时店员用 POS/小程序验证（若未来对接）；当前可 **手工标记核销**。 |
| **系统做什么** | RegionPack 支付提示；券元数据；预留 OMS 对接字段。 |
| **能力映射** | REG-01, ORCH-02, LOC-01 |

### US-OUT-TH-005 合规留痕：OA 订阅证据与敏感词拦截

| 字段 | 内容 |
|------|------|
| **谁用** | 合规负责人 |
| **目标** | 平台审计或纠纷时可导出同意证据；营销话术不踩线 |
| **怎么用** | 1）**合规**配置「营销类」目的订阅文案版本 v3。 2）用户通过 OA 完成订阅后 **系统** 写 **CON-02** 记录（渠道=line_oa, locale=th-TH）。 3）群发前 **系统** 执行 LOC-02；命中高敏词则阻断。 |
| **系统做什么** | Ledger 只增；导出 CSV；与发送闸门 CON-03 联动。 |
| **能力映射** | CON-01, CON-02, CON-03, LOC-02 |

## 5. 德国 / 柏林锚点场景（合规与消费者）

### US-OUT-DE-001 租户开启 EU 严格合规模式

| 字段 | 内容 |
|------|------|
| **谁用** | 租户管理员 / 合规官 |
| **目标** | 德国店默认 double opt-in、目的分拆、全局退订可用 |
| **怎么用** | 1）**管理员**在租户设置选择 `compliance_profile = eu_strict`。 2）**系统**强制开启：营销单独勾选、订阅确认邮件/消息二次确认（流程可配置）。 3）**系统**默认关闭「将画像用于再营销」直至单独同意。 |
| **系统做什么** | 租户级策略模板；UI 与 API 校验；影响 CON-01 表单与 CON-03 逻辑。 |
| **能力映射** | REG-02, CON-01, CON-02, CON-03 |

### US-OUT-DE-002 消费者仅同意事务性消息

| 字段 | 内容 |
|------|------|
| **谁用** | 终端消费者（欧盟）；协同：系统按策略 |
| **目标** | 只收物流/订单通知，不收促销 |
| **怎么用** | 1）结账页仅勾选「订单状态通知」。 2）**系统**写 CON-02（purpose=transactional）。 3）**运营**尝试把该用户圈进促销计划时 **系统** CON-03 **拦截** 并提示原因。 4）App/网站营销入口对该用户 **灰显** 或需二次 opt-in。 |
| **系统做什么** | 目的维度 marketable 标志；发送前闸门；前端偏好 API。 |
| **能力映射** | CON-01, CON-02, CON-03 |

### US-OUT-DE-003 消费者单独同意促销并留痕

| 字段 | 内容 |
|------|------|
| **谁用** | 终端消费者 |
| **目标** | 明确愿意收促销，且品牌可证明 |
| **怎么用** | 1）用户在偏好中心勾选「促销与灵感」(marketing)。 2）**系统**展示当前策略版本与摘要链接。 3）用户确认后 **系统** 写 CON-02（含 policyVersion、时间戳）；若启用 double opt-in，第二封确认到达后才 `marketable.marketing=true`。 |
| **系统做什么** | Ledger；版本化策略；可导出证据包。 |
| **能力映射** | CON-01, CON-02, REG-02 |

### US-OUT-DE-004 一键全局退订

| 字段 | 内容 |
|------|------|
| **谁用** | 终端消费者 |
| **目标** | 停止所有营销通道 |
| **怎么用** | 1）用户在偏好中心点击「停止所有营销」。 2）**系统** CON-04：将所有 marketing 目的标记撤回；**取消**已排期未发送的营销任务；通知 ESP/推送占位适配器停止该类订阅。 |
| **系统做什么** | 与队列、CH-01 下游状态同步；审计日志。 |
| **能力映射** | CON-04, ORCH-02, CH-01 |

### US-OUT-DE-005 撤回营销同意后保留合同数据、清理画像字段

| 字段 | 内容 |
|------|------|
| **谁用** | 终端消费者；协同：合规官审核任务 |
| **目标** | 合法保留发票/履约数据，删除营销画像 |
| **怎么用** | 1）用户撤回 marketing 同意。 2）**系统**停止画像用途，触发 **匿名化任务**：清除用于 profiling 的标签与事件副本，保留订单与发票关联主键。 3）**合规官**在任务队列确认执行完成。 |
| **系统做什么** | 数据生命周期策略；可配置保留集；执行记录。 |
| **能力映射** | CON-04, CON-02（撤回记录）, REG-02 |

### US-OUT-DE-006 关闭 AI 个性化后仍可使用核心功能

| 字段 | 内容 |
|------|------|
| **谁用** | 终端消费者 |
| **目标** | 不用 AI 推荐也能下单/咨询 |
| **怎么用** | 1）用户关闭「个性化推荐/AI 辅助」。 2）**系统** AI-04：列表排序改为中性规则；AI 草稿按钮隐藏或仅展示通用模板。 3）自动回复若启用，必须标注「自动回复」且不调取已撤回用途数据。 |
| **系统做什么** | 偏好与 AI 服务开关联动；策略引擎尊重标志位。 |
| **能力映射** | AI-04, CON-04, E2 |

## 6. AI 人审场景（与发送 / 画像联动）

### US-OUT-AI-001 坐席生成跟进草稿并发送

| 字段 | 内容 |
|------|------|
| **谁用** | 一线坐席 |
| **目标** | 快而合规地回复多语种咨询 |
| **怎么用** | 1）**坐席**打开会话，点「生成草稿」。 2）**系统** AI-01：仅拉取 **已同意目的** 内允许使用的上下文 + 话术库，生成 3 条候选。 3）**坐席**编辑后点击发送 → **系统** 经 CON-03 与 LOC-02 后走 MSG-01 / CH-01。 4）**系统** 写审计：模型版本、输入哈希、坐席最终稿。 |
| **系统做什么** | HITL；同意闸门；禁忌扫描；日志。 |
| **能力映射** | AI-01, CON-03, LOC-02, MSG-01, CH-01 |

### US-OUT-AI-002 运营确认会话摘要与标签

| 字段 | 内容 |
|------|------|
| **谁用** | 私域运营 |
| **目标** | 画像准确且可解释 |
| **怎么用** | 1）**运营**对某客户点「生成摘要与标签建议」。 2）**系统** AI-02 输出建议标签列表（带引用句）。 3）**运营**勾选确认 → **系统** 写入正式标签；未确认不入库。 |
| **系统做什么** | 建议态与正式态分离；版本记录。 |
| **能力映射** | AI-02, ORCH-01 |

### US-OUT-AI-003 主管采纳意图与优先级建议

| 字段 | 内容 |
|------|------|
| **谁用** | 客服主管 |
| **目标** | 队列公平、高意向优先 |
| **怎么用** | 1）**系统** AI-03 对队列中会话打分并展示理由片段。 2）**主管**一键采纳分配或手动调整。 3）**系统** 记录覆盖原因（可选填）。 |
| **系统做什么** | 可解释排序；人工覆盖审计。 |
| **能力映射** | AI-03, SLA-01 |

### US-OUT-AI-004 市场活动文案 A/B 经合规放行

| 字段 | 内容 |
|------|------|
| **谁用** | 市场；协同：合规 |
