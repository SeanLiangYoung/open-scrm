# 出海私域运营：方法论 × 本地化 × AI — 产品设计（草案）

> 本文档由 **brainstorming** 流程产出：多角色 PM subagent 观点碰撞 + 公开市场检索汇总。  
> **锚点市场（示例）**：**东南亚** 为增长侧主叙事区（泰国 / 曼谷都市圈仅作 **RegionPack 示例**，同一套方法论可落到印尼、越南、马来、菲等，IM 主阵地以各国 Pack 配置为准，如印尼偏 **WhatsApp**、泰国偏 **LINE OA**）；欧盟合规以 **德国 / 柏林** 为严格同意与留痕代理。产品层应支持「区域包 RegionPack」扩展，而非写死单一国家。

---

## 1. 背景与仓库语境

- Open SCRM 已完成 **S1–S6**（企微集成、统一消息、日聚合看板、获客活码、质量门禁等），技术栈为 **Midway + PostgreSQL + Redis + 网关聚合**。
- 国内「私域」默认 **微信 / 企业微信**；出海场景主阵地常为 **WhatsApp Business API（WABA）**、**LINE OA**、**Meta Messenger** 等，且强依赖 **BSP / 平台政策** 与 **本地支付、节庆、时区**。
- 本设计不把 Open SCRM 重新定义为「仅海外」，而是增加一层：**区域化私域运营（Region-aware Private Domain）**，与现有企微能力 **并行、可插拔**。

## 2. 多角色 PM 碰撞结论（摘要）

| 人设 | 核心主张 | 对产品的影响 |
|------|-----------|----------------|
| 方法论与指标 PM | 分层 + SOP + 信任内容 + 数据闭环 + **同意优先** | 指标树、人群包、触达频次上限、归因从广告 → IM → 订单 |
| 东南亚增长 PM | **LINE / WhatsApp 等国别差异**、节庆日历、本地钱包与 COD、双语客服、忌照搬微信群 | 渠道模板「**东南亚区域包**」（示例：`th-bangkok` 偏 LINE OA；`id-jakarta` 可偏 WABA）：菜单、券、时区排班 |
| 欧美合规 PM（德 / 柏林） | **Consent ledger**、目的分拆、撤回与营销停止联动、AI 不伪装人工 | 同意记录、目的映射表、全局退订、AI 输出强制披露 |
| AI-native PM | **人审后发**、摘要→标签建议态、意图路由可解释 | v1 不做无人批量营销；eval + 审计日志 |

**碰撞共识**：下一期价值 = **「合规同意 spine + 区域 playbook + 人审 AI 增效」**；争议点（留待迭代细化）：是否在本仓库内直接接 WABA BSP，还是先抽象 **MessageChannel** 与 **RegionPack** 文档 + Mock 通道验证。

## 3. 可复用方法论（从市面经验抽象）

以下综合公开案例文与出海实践文（私域神器、出海指南、智齿/WABA 介绍、GDPR 营销合规综述等），抽象为 **7 条原则**（与 subagent 对齐并略展开）：

1. **会员与分层**：RFM / 生命周期 / 渠道来源；不同层不同频次与权益。  
2. **SOP 化**：拉新 → 培育 → 转化 → 复购 → 裂变；每阶段有关卡指标与升级条件。  
3. **信任型内容**：场景解法、本地案例、售后与合规背书；减少「纯促销栏」疲劳。  
4. **数据闭环**：统一 ID 串联广告、落地页、IM、订单（或线索）；可复盘漏斗。  
5. **矩阵与分工**：按国家 / 语言 / 人设拆号，分散封禁风险，支持 A/B 话术。  
6. **同意优先（尤其 EU）**：opt-in 可证明、易撤回；营销与事务性消息 **目的分拆**。  
7. **本地化 ≠ 翻译**：时区、节庆、支付组合、语气、禁忌词（宗教 / 王室 / 医疗宣称等）。

**最小指标树（建议）**

- **北极星**：同意可触达用户的 **可归因毛利 / 90 日 LTV**（或团队现阶段可用的代理：已同意联系人带来的成交 GMV）。  
- **领先指标**：有效同意率；24h 内有效对话率；SOP 阶段转化率；矩阵健康度（可触达账号占比、投诉 / 封禁率）。

## 4. 区域本地化：两个锚点深度摘要

### 4.1 东南亚（代表锚点：泰国 / 曼谷都市圈）

> **区隔说明**：东南亚各国 IM 与支付习惯不同（例如印尼、马来、菲 **WhatsApp** 权重常更高；泰国等 **LINE OA** 权重常更高）。以下以 **泰国曼谷** 为具象化示例，便于写场景；产品通过 **RegionPack** 按国切换默认渠道与变量。

- **本示例首选 IM**：**LINE OA**（菜单、券、预约、客服分流）；辅助 **Facebook Messenger**（广告落地咨询）；**TikTok** 常作种草后 **导流至 LINE OA**（他国 Pack 可改为「TikTok → WhatsApp」等）。  
- **文化与时机（泰示例）**：佛教与王室相关敏感；宋干、水灯、跨年与中国春节在泰消费等 **排期型** 活动；**UTC+7** 高峰排班。东盟其他国家需替换为本地节庆（如开斋节、国庆等，见区域矩阵扩展行）。  
- **支付（泰示例）**：PromptPay、银行转账、COD、TrueMoney 等；高客单需分期 / 到店说明。印尼等可换 OVO、DANA、GCash 等（Pack 字段）。  
- **常见失误**：照搬微信群；仅机翻无再创作；忽视 OA/WABA 订阅与 BSP 政策；客服 SLA 不按 **当地时区**。

### 4.2 德国 / 柏林（合规代理）

- **习惯差异**：严格 **opt-in**（营销邮件常需 **double opt-in** 证据链）；GDPR **lawful basis** 与 **ePrivacy** 对电子营销地址的额外要求；撤回后须停止自动化与用于营销的画像。  
- **产品硬约束**：**Consent ledger**（时间戳、文案版本、渠道）；**目的映射**（订单通知 ≠ 促销 ≠ 画像/再营销）；**全局退订** 与下游激活系统联动。  
- **AI**：不得伪装人工；基于个人数据的推断需在隐私政策披露；用户可关闭个性化建议而不影响核心服务（合理范围内）。

## 5. AI 能力边界（v1 共识）

**三组能力包（人审后发）**

1. **多语种话术辅助**：基于已授权上下文与话术库生成草稿 → **坐席 / 组长**选用或改写后发送。  
2. **会话小结 → 标签建议**：摘要与标签为 **建议态**，人工确认写入 CRM。  
3. **意图与路由建议**：优先级与队列建议 + **可解释引用**；主管可覆盖。

**v1 明确 NON-goals**

- 不对未明确同意联系人自动批量营销；不提供规避退订能力。  
- 不做站外爬取名单、伪个性化骚扰。  
- 不输出需持牌的法律 / 医疗 / 税务确定性断言。  
- 不承诺「规避平台检测」类话术。

以下按 **YAGNI** 排序：先做 **文档与模型契约**，再接具体 BSP。

| ID | Epic | 说明 |
|----|------|------|
| E1 | **区域包 RegionPack** | 国家/城市元数据：默认 IM、节庆日历钩子、支付提示、禁忌词类目、时区；可 JSON 驱动。 |
| E2 | **同意与偏好 spine** | Consent ledger、目的、版本、撤回；与「可营销」标志联动（EU 模式默认严格）。 |
| E3 | **渠道抽象 Channel Adapter** | 在 `message-service` 或 integration 层预留 **WABA / LINE / Messenger** 适配接口；开发期 **Mock 通道** 跑通编排。 |
| E4 | **运营编排（轻量）** | 分群 + 触达计划 + 频次上限；复用现有统一发送与幂等；区域包决定默认模板变量。 |
| E5 | **AI 人审层** | 草稿生成、标签建议态、审计日志；与 E2 耦合（仅对同意目的调用）。 |
| E6 | **分析与归因扩展** | 广告 / UTM → 加好友 / 会话 → 成交的字段预留（无订单时可先用手工导入或 webhook）。 |

## 7. 用户场景与用户故事（User cases）

### 7.1 跨区域通用（方法论 PM）

1. **作为出海运营负责人**，我希望按国家/渠道管理 IM 矩阵与权限，以便归因清晰且分工合规。  
2. **作为私域操盘手**，我希望分层人群进入不同 SOP 分支，以便在控制频次下提高培育效率。  
3. **作为本地化同学**，我希望维护多语言素材与禁忌词库，以便一线话术一致并降低风险。  
4. **作为增长同学**，我希望广告点击到加好友到会话到订单可回传，以便优化投放与私域 ROI。  
5. **作为客服主管**，我希望 SLA、升级规则与质检可配置，以便高价值客户不漏跟。

### 7.2 东南亚（以泰国 / 曼谷为示例；东南亚 PM）

1. **运营负责人**：宋干 / 水灯排期用 **LINE OA**（示例）欢迎语 + 关键词回复 + 券模板群发，并监控屏蔽率。  
2. **增长负责人**：TikTok 落地页统一导 **LINE OA**（示例），A/B 泰语首屏 + **泰铢标价**，追踪关注 → 首单。  
3. **客服负责人**：Messenger 与 LINE **统一工单与泰/英话术库**，排班对齐 **东南亚当地时区**（示例 UTC+7）。  
4. **区域负责人**：门店与线上 **同券同库存**，减少 COD / 地址纠纷。  
5. **合规负责人**：记录 OA 订阅证据、敏感词拦截、支付跳转白名单，降低封号与拒付。

### 7.3 德国 / 柏林（合规 PM）

1. 用户仅勾选事务性消息时，营销入口灰显且不再二次骚扰。  
2. 单独勾选「促销」时，ledger 记录版本与时间（字段最小化由法务定稿）。  
3. 一键全局退订，同步停止邮件 / 短信 / 应用内营销类 push。  
4. 关闭 AI 个性化后仍为中性排序；自动回复显式标注非人工。  
5. 撤回营销同意后保留合同与发票数据，删除或匿名化仅用于画像的字段。

### 7.4 AI 人审（AI PM）

1. 坐席点「生成跟进」→ AI 出 3 条草稿 → 坐席选用后发送。  
2. 运营查看会话摘要与标签建议 → 勾选确认写入画像。  
3. 客服主管查看意图与紧急度建议 → 确认后分配 SLA。  
4. 市场活动 A/B 文案由 AI 生成 → 合规勾选版本后排期。  
5. 知识管理员从工单生成 FAQ 草稿 → 校对后发布知识库。

## 8. 架构与数据流（概念）

```text
[广告 / TikTok / Meta LP] --UTM--> [Landing / OA 关注]
       |
       v
[Consent capture] --> [Consent Ledger] --> [Marketable flag per purpose]
       |
       v
[Orchestrator: Segment + SOP + frequency cap]
       |
       v
[Channel Adapter: WeCom | WABA | LINE | Mock] --> [message-service 幂等发送]
       |
       v
[Analytics: funnel + matrix health]     [AI: draft/summary --human gate--> CRM]
```

**错误处理**：通道失败重试、退订与撤回 **立即** 抑制队列；AI 失败降级为模板话术。

**测试**：Mock 通道 E2E 覆盖「同意 → 培育一步 → 发送 → 撤回后不再发送」；区域包单元测试（节庆日期、禁忌词命中）。
