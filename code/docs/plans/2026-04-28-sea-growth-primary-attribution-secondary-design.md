# 出海私域：东南亚增长为主、归因为辅 — 方向拍板（2026-04-28）

> **状态**：经 brainstorming 多角色 PM 调研后，干系人明确 **B 为主、C 为辅**。本文档为 **执行级方向约束**，与主设计 [出海私域运营：方法论 × 本地化 × AI](./2026-04-28-outbound-private-domain-localization-design.md) 并存；实现拆解见后续 **writing-plans** 产出的实现计划。

---

## 1. 取舍声明

| 维度 | 选择 | 含义 |
|------|------|------|
| **主叙事（B）** | 东南亚起量 | 频控 / 静默时段、区域策略矩阵、LINE OA / WhatsApp 差异化、本地支付与 COD 话术与状态、TikTok（及同类）→ IM 进线与首响剧本 |
| **辅线（C）** | 投放与私域联合归因 | 在不大改主栈的前提下，优先 **身份键与事件口径** 的 **MVP**，为漏斗与看板供数；**不做**「大而全 BI」优先于 B |

**不变底线**：现有 **同意闸门**（`consentPurpose` / `consent_record`）与 **目的分拆** 不因「增长优先」而削弱；B 的功能（频控、活动编排）**默认读取** RegionPack / 策略配置，并与同意范围校验 **串联**（先可营销，再谈频控与时段）。

## 2. 分阶段交付（建议顺序）

### 阶段 A — B 的「护栏与可运营」（P0）

1. **策略引擎 MVP**：每用户 / 每活动 / 每渠道的 **频次上限** + **静默时段**（按 RegionPack 时区，如 `Asia/Bangkok`）；发送前与统一消息 API 集成；可配置、可审计拒绝原因（含 `policy_violation` 类占位）。
2. **区域包可读 → 可执行**：在现有静态 RegionPack 目录之上，增加运营可理解的 **策略维度**（不必首版上 UI 全量，可先配置表或 JSON + 管理 API）。
3. **双语与模板分层**：话术库区分 **顾客侧 locale** 与 **督导侧中文摘要** 字段；与模板变量、禁忌词分区挂钩（与主设计 §4.1 一致）。

### 阶段 B — B 的「离钱近」闭环（P1）

4. **TikTok / 广告进线 → IM**：进线事件携带 **活动 / 创意 / 落地变体** 标识；坐席侧 **首句剧本** 与队列分派规则（与同意范围绑定）。
5. **COD / 本地支付轻闭环**：会话侧结构化节点（下单意向 → 凭证 → 发货/签收占位）；**单独更严频控**，避免催付类消息触发渠道投诉。

### 阶段 C — C 的「窄带归因」（与 A/B 并行小带宽）

6. **身份键 MVP**：匿名点击 / 落地页会话 → **加 IM / 首条消息** 的稳定关联策略（冲突规则、多设备说明文档化）；与 `message_log.extra`、获客模块已有字段 **对齐字典**。
7. **事件 taxonomy 最小集**：命名、必选维度、与 `daily_stat` / 现有 analytics **口径对齐**；禁止「同名不同义」堆事件。
8. **看板预置一页**：渠道 → 落地 → 加 IM → 首响 →（占位）订单；突出 **归因缺口率**、**未解析身份占比**，服务运营与投放复盘。

## 3. 与仓库现状的映射（事实锚点）

- **统一消息**：`POST /api/v1/messages/send`、幂等、`messageType` 含 Mock 出站；发送前策略引擎应挂在此路径 **之前或之内**（与网关、租户上下文一致）。
- **同意**：`consent_record` + `consentPurpose` 闸门已存在；B 的编排 **不得绕过**。
- **RegionPack**：`message-service` 内已有静态目录示例；本方向要求演进为 **策略与频控的数据源**，而非仅展示字段。
- **归因辅线**：`message_log.extra` 已可承载 UTM 等；C 的重点是 **键与 taxonomy**，而非再立「存 UTM」独立项。

---

## 4. 成功标准（季度末可验收）

- **B**：在至少一个 RegionPack（如 `th-bangkok`）下，可对单用户演示 **超频 / 静默拦截** 与 **可解释拒绝**；有一条 **TikTok→IM** 或等价进线的 **E2E 或脚本化演示路径**（可无真实 BSP，Mock 亦可）。
- **C**：发布 **事件字典 v0.1** + **身份键规则 v0.1**；预置看板能展示 **漏斗阶段人数** 与 **归因缺口** 两类指标（允许部分阶段手工导入占位）。

---

## 5. 显式 NON-goals（本方向文档期内）

- 不承诺 **真实 WABA/LINE BSP** 全量商化上线（仍走适配器 + 沙箱/双写策略，见主设计 Epic E3）。
- 不以「弱化同意」换取起量；若策略与同意冲突，**同意优先**。
