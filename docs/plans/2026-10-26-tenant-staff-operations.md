# 本企业员工目录与运营人员选择计划

用户已要求持续自主推进。此项承接夜间计划中“可信企业员工查询”和运营分配的明确缺口，在当前可靠性修复完成后并行执行；不改平台管理员的全局用户管理语义。

## 目标与设计

新增经网关的 `GET /api/v1/staff`，只返回认证企业中 `status=1` 的员工基本身份。响应为 `{ success:true, data:{ list,total,page,pageSize } }`，每行仅含 `id`（保留精确十进制字符串）、`username`、`realName`（可空）。不返回密码/哈希、角色、手机号、邮箱、外部平台身份或其它企业信息。

企业与操作者来自可信网关头/认证上下文，缺失/非法身份401；查询只接受 `page`、`pageSize`、`keyword`，默认1/20、pageSize1–100，拒绝数组、歧义数字、非安全分页偏移及过长关键词。关键词为用户名或真实姓名的大小写不敏感子串，必须参数化并保持企业条件。稳定排序使用username及id。普通已登录运营员工可查询本企业启用同事，平台全局`/users`保持既有管理员路径限制。

SOP提醒支持选择多名本企业启用员工；客户创建/编辑支持可选分配员工。界面使用远程关键词检索，明确当前搜索结果而非声称列出所有员工；保留已有配置中未出现在当前搜索页的ID，不静默丢弃。前端把ID转换成数字前校验安全正整数。新建分配步骤只有在后端员工归属校验验证通过后才启用，不能以页面选择代替服务端检查。

消息通知创建必须在任何保存前验证全部员工属于调用企业且启用；非法、缺失、外企或停用目标拒绝，避免孤立通知和错误成功计数。复用共享数据库的权威user表，不引入跨服务实体包或全局用户列表调用。

## 独立任务及验收

1. **Auth目录与Gateway路由（主执行者）**：新增staff controller/service或合适独立服务文件与单测、精确路由和文档。先失败用例，再实现。至少覆盖正常列表、企业隔离、停用过滤、搜索、分页、缺失身份、非法query、字段白名单8类。
2. **通知接收人校验（message子任务）**：参数化企业/状态查询，整批在保存前校验，保留结果契约；测试有效/缺失/外企/停用/空及非法ID、重复ID处理。不得实际发送外部消息。
3. **运营人员选择（customer子任务）**：SOP多员工提醒、客户分配与分配步骤，使用新API远程搜索；创建/编辑和旧配置往返验证，不查询全局users。浏览器至少覆盖同事选择、请求数字ID、安全ID拒绝、搜索失败反馈、保留已有选中值。
4. **真实隔离HTTP（runtime子任务）**：真实auth/gateway和PG16，两个企业真实登录；普通非管理员可查询本企业、不能通过头/query伪造其它企业；精确验证字段白名单与停用过滤；通知与客户归属边界用实际数据库或HTTP验证，所有资源清理并核对。

## 文件归属与依赖

主执行者拥有auth新staff文件、gateway配置/路由测试、共享CI和总计划。message任务拥有通知服务/测试及独立报告。customer任务拥有operation前端人员选择相关文件及独立浏览器测试，需先等上一批CustomerList稳定并与其它前端写入者交接。runtime任务拥有新的隔离staff HTTP脚本/独立Playwright配置和报告。禁止多人覆盖同一文件。
