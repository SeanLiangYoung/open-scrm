# 服务运行就绪与统一验收入口

承接夜间持续计划、员工目录和企业登录改进。用户已授权持续推进；本批在当前功能闭环之外补齐实际运行证据和可重复入口，不扩展财务业务或连接真实第三方账号。

## 已知基础

新初始化PG16上的独立审计已验证acquisition/integration/analytics/asset/content-generation五服务、16实体和195映射列。表存在和ORM读取成功不等于应用真正能启动，也不等于HTTP接口正确。本批填补这个证据缺口。

## 任务与验收

1. **五服务实际启动**：在全新PG16/Redis上，逐一clean构建并以随机loopback端口实际启动上述五服务，确认metadata与已实现health接口可达。每项记录启动/停止结果；不把不存在的health路由假定为200。读取各自事实源和配置；存储/输出目录指向临时工件，禁止真实OSS、LLM、企微等外部调用。测试子进程从启动前限制出站连接为自己的DB/Redis/HTTP资源，记录被拒绝的尝试；任何外部提供方结果均不得算实际验证。
2. **分析实际网关HTTP**：真实登录的两个企业、实际analytics服务和PG16，覆盖手动日聚合、overview有/无快照、区间事件累加/库存末日、归因窗口和客户归属过滤、双企业与伪造身份头边界。至少6个明确业务场景，给出精确数据库夹具及结果。日期/校验错误按本接口已有契约记录，不为测试任意改变全局错误码。
3. **统一验收入口**：新增独立runner，按static/browser/database/http分组或all串行调用已经验证的命令，保存每阶段日志、退出码、耗时及JSON清单；失败不能被tee掩盖或当通过，未知/跳过分开。支持明确报告目录和缺失依赖提示，不自动安装/下载，不触碰现有数据库，不重复造一套业务实现。只编排经过审查的隔离脚本和模拟浏览器套件。
4. **复验与CI**：主执行者独立运行新增就绪/分析链和统一入口（先分组再必要的最终all），修复实际缺陷，更新事实文档。CI使用对应分组或明确脚本，上传证据；没有远程执行则不声称CI已绿。

## 并发归属

SOP/runtime任务拥有五服务boot脚本/报告；message/consent任务拥有分析HTTP脚本、独立用例/报告；customer任务拥有统一runner及其错误传播自检/说明。主执行者拥有共享CI、总计划及源代码修复协调。新脚本独立文件，禁止互相覆盖。

共享服务dist构建和真实HTTP运行必须协调串行，避免一个clean构建删除另一服务启动所需文件；准备测试/文档、模拟浏览器和内存转译数据库检查可并行。主执行者正在独立验收M10时，其他执行者先准备、不启动相同服务。
