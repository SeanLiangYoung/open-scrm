# SOP动作配置严格执行

独立当前DTO和真实方法探针确认：true/1e0/0x1/数组等员工值被Number转为员工1；站内通知DTO也可能转换非规范字符串；不存在/外企标签命中空数组仍保存并把SOP记完成；负延迟被跳过后立即执行。当前目标服务仍检查企业/启用，不把这些同企业误操作夸大成跨企业发送。

## 实施边界与验收

1. 步骤保存入口为nested步骤建立运行时校验，不能只以TypeScript类型声明代替；只支持已有动作1–5，校验非空名称、非负有界延迟与已支持单位、动作对象类型和对应必需字段。旧JSON字符串/已文档别名按明确规范兼容，不接受宽松Number转换。
2. 员工/标签/目标相关ID只接受JSON安全正整数或已文档规范十进制字符串；布尔、数组、指数/十六进制/空白/小数/溢出全部拒绝且无下游调用。提醒多人去重、有效自己与同事组合保持。
3. 执行器对绕过保存的旧数据库配置也先校验，不能因DTO存在就信任；非法动作/负延迟记录明确失败，不推进currentStep、不执行后续动作。保持既有暂停/取消/恢复和长延迟分段。
4. 标签服务的全批存在/同企业拒绝由标签任务负责，SOP动作任务不改CustomerService；此处验证下游拒绝被记录失败且不继续。成功只认确切业务响应，不能HTTP200即完成。
5. 至少20新增DTO/保存/执行回归和4实际SOP HTTP/PG场景：无效员工配置不变更客户、无效提醒无通知、无效标签失败无进度、负延迟不立即副作用；合法提醒/分配和既有Mock消息控制保持。精确SQL、退出码和清理为验收条件。

SOP任务拥有operation步骤DTO/模板保存校验/执行器及新测试，禁止改customer/message归属服务或其他前端。root维护计划和共享文件。all40结束前只准备红测，生产源码/dist冻结；随后按授权实施，真实HTTP串行。

执行裁定（根任务）：最大延迟365天，整数非负，现有实际支持单位仅minute/hour/day；second未实现，本批明确拒绝，不宣称支持。30day原例和Node长等待分段必须保留。正常group触发只写groupId，原有tag/assign会因无customerId拒绝；新增防护针对legacy混合customer/group字段及template/trigger类型不匹配，不宣称正常group已发生同号误操作。

元数据小裁定（根任务）：步骤1/3的optional action.templateId作为消息模板引用，仅接受JSON正整数INT32，拒绝字符串/布尔/null。保存与执行均校验；未提供时不新增payload属性，提供时条件转发，不能替换请求正文或extra。下游message验证本企业存在，disabled/异channel作为元数据仍允许。其他未知动作metadata保留。提醒/标签原始数组最多100，与下游一致，去重后执行；员工/客户/群和execution BIGSERIAL仍为正safe整数，不被模板INT32限制。
