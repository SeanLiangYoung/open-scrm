# 本企业员工选择：前端契约验证

本报告记录2026-10-26员工目录阶段的前端交付。依据[本企业员工目录计划](../plans/2026-10-26-tenant-staff-operations.md)，前端只查询 `GET /api/v1/staff`，不读取全局用户管理API。这里的Playwright测试拦截API，证明页面行为和请求形状，不等同于实际员工目录或消息发送链验证。

## 控件与提交语义

新增[共用选择控件](../../code/apps/operation-platform/src/components/TenantStaffSelect.vue)和[搜索适配](../../code/apps/operation-platform/src/composables/useTenantStaff.ts)：输入关键词远程搜索，固定请求第一页、pageSize20，空关键词省略。返回行使用精确字符串ID、username及可空realName；界面明确这是当前搜索结果，不声称一次列出全部员工。

已配置员工不在当前结果页时，仍显示已配置编号；曾获取的姓名缓存跨搜索保留。新搜索发出后，旧请求的结果或错误不会覆盖新请求状态。搜索失败显示错误，不静默删除选中项。

ID在选择状态中保留字符串。提交前只接受规范十进制安全正整数，再转换为数字；目录中的超大ID禁选，旧配置中的超大员工ID保持原文显示并阻止SOP写入，避免精度丢失或静默丢人。前端检查不替代服务端企业与启用状态检查。

[客户列表](../../code/apps/operation-platform/src/views/customer/CustomerList.vue)创建/编辑支持可选单员工分配。新选择提交数字 `followUserId`；未选择时省略，编辑时保留原分配；未改变已有分配时也省略字段，不把未出现在搜索页的员工重新写成空。该功能不自动指定员工1或当前登录员工。清空选择在现有客户上表示保持原分配，界面有相应提示；没有新增解除分配API。

[SOP编辑](../../code/apps/operation-platform/src/views/sop/SopEdit.vue)提醒步骤支持多员工选择，可与显式“提醒当前登录员工”并用；数字ID去重提交，保留既有其他动作元数据。客户分配步骤4已启用，选择员工后提交 `actionContent.followUserId`；群SOP仍不允许客户专用分配/打标签步骤。已有 `userId` / `staffId` 等兼容配置在加载时归一化，合法历史接收人不会因当前搜索页缺失而丢失。

同时补充确定性提交边界：纯空白流程名或消息步骤正文在API写入前拒绝；未配置步骤的有名新草稿仍允许保存。可选描述在新建或原本为空时省略；明确清空已有描述提交null，与更新DTO新增允许值一致。提醒步骤没有额外强制正文规则。

## 测试驱动与最终证据

最初新增的客户员工选择和SOP分配两个浏览器用例在旧页面失败，确认入口缺失。另新增的空白正文/名称两项回归先失败后修复；描述省略/清空两项也先观察失败再修复。

最终独立配置执行**12项、0跳过，全部通过**：

1. 客户创建选择同事，提交数字员工ID，没有全局users请求或正文企业身份。
2. 客户编辑保留不在当前搜索页的原员工，未改变时不重新提交分配。
3. 提醒保留既有接收人/extra，增加同事和自己，重复的自己仅保留一次。
4. 新客户分配步骤可选并提交数字员工。
5. 搜索失败反馈，原选择保留。
6. 超大员工ID禁选，旧超大接收人阻止写入并保留原编号。
7. 乱序搜索响应保留最新结果。
8. 客户编辑可改分给选中的安全数字员工。
9. 纯空白消息步骤在任何模板/步骤写入前拒绝。
10. 纯空白流程名称在写入前拒绝。
11. 有名称、无步骤的新草稿仍允许创建，且空描述省略。
12. 清空既有流程描述提交null。

可复现命令：

```bash
cd code/e2e
./node_modules/.bin/playwright test --config staff-selection-contracts.config.ts
```

[独立配置](../../code/e2e/staff-selection-contracts.config.ts)使用127.0.0.1:3106和strictPort，结束后停止自己启动的Vite；[用例源码](../../code/e2e/tests/staff-selection-contracts.spec.ts)使用Mock身份与拦截请求，不连接数据库或真实员工目录。

相关文件eslint、运营前端 `vue-tsc --noEmit` / `vue-tsc -b` 以及Vite生产构建通过；仍存在既有较大分块提示，未关闭提示或规则。范围内差异检查通过。既有25项运营回归及实际staff HTTP链由主执行者独立重跑记录，不混入这12项的计数。

## 边界

目录仅展示当前搜索第一页；可继续输入更精确关键词，不提供“全部员工”保证。既有配置中的未知员工显示保留标签，并不证明其仍已启用或属于本企业；实际保存/执行需由后端权威检查。前端本批没有实际发送、部署、提交或推送，没有修改既有数据库或全局用户管理行为。
