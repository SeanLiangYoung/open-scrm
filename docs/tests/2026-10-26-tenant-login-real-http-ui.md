日期：2026-10-26（Asia/Shanghai）。实际 auth、gateway、Vite、Chromium 与一次性 PostgreSQL16 / Redis；没有接口响应 Mock，没有注入登录存储，没有真实消息。

## 复现与安全边界

仓库根执行：

```bash
node code/scripts/test/overnight-tenant-login.cjs
```

脚本使用仅绑定 loopback 随机端口的独立 PostgreSQL16、Redis，等待 PostgreSQL TCP 就绪后执行完整初始化 SQL。夹具为两个企业的同名普通员工、各自不同的密码、一个唯一用户名普通员工、一个停用员工。密码通过本地bcrypt实际哈希；不改既有数据库。

确认 `dist` 无受版本管理文件且为忽略目录后，auth / gateway执行 `mw build --clean` 并在独立端口启动。Vite绑定本次网关且 `strictPort`。未参与验证的网关依赖指向测试拥有的503隔离监听器，避免访问项目已有服务；不伪造成功的主页业务数据。

用实际登录接口取得的access/refresh凭证验证正常链路。另用本次随机测试密钥生成过期access、过期refresh和停用用户refresh夹具，用于验证拒绝边界；这些是受控测试凭证，不是自然历史会话。浏览器凭真实登录表单取得身份，不注入token。

结束、中断或异常均清理本次服务、Vite、测试进程、隔离监听器及容器，并验证其退出或不存在；清理失败令总体结果失败。

## 首次失败与修复

首次完整运行 **3项通过、2项失败**：新登录/刷新DTO的非法输入实际返回Midway默认422，而计划契约要求400。认证逻辑和真实企业选择浏览器场景通过，两个严格400断言失败。没有将测试放宽成接受422。

实际路由改为 `@Validate({ errorStatus: 400 })` 后，使用稳定的认证、网关及两端登录代码重新清洁构建，完整验证 **5/5项通过**（4项HTTP、1项真实Chromium）。

## 五项覆盖

1. **歧义身份失败关闭**：省略企业编号的同名账号返回400和填写企业编号的提示；伪造 `x-corp-id` / `x-user-id` 或只放在query中的corpId均不能选择企业。错误响应不含token、用户、候选企业或角色信息。
2. **企业与密码严格匹配**：显式1001/1002使用各自密码得到正确企业JWT，并访问各自员工目录。错误企业不回退，跨用另一企业密码、未知账号及停用账号统一401。唯一用户名不填企业仍可登录；两个同名用户均为普通非管理员。
3. **输入严格类型**：字符串企业编号、科学计数字符串、零/负数、小数、null、布尔、数组、对象及超过安全整数的数值，实际HTTP均400且无凭证。
4. **刷新用途与访问边界**：两企业实际签发的refresh在无Bearer时能续期并保留正确企业；即使请求带过期access，也能凭有效refresh续期。无效、过期、access冒充refresh、停用用户refresh均401；非法refresh DTO为400。refresh作为Bearer访问员工目录被401拒绝，`/refresh-token/extra`不享受精确公开路径豁免。
5. **真实运营登录页**：同名账号不填企业时收到提示，用户名/密码保留且没有token；填企业1002但使用企业1001密码时仍失败且不存token；改为企业1002密码后提交数字corpId并登录。浏览器实际认证请求员工目录，只返回企业1002员工，确认正确企业上下文。

最终 PostgreSQL **16.13** 查询：两条同名普通员工与唯一用户名成功登录；停用账号仍停用且最后登录时间为空。`message_log` 和 `notification` 均0条。结果JSON的 `testsPassed`、`cleanup.passed`、`passed` 均为 `true`。

## 复审与限制

只读复审确认：显式企业查询无回退；省略时最多读取两条判断歧义；密码错误及停用统一失败；刷新校验签名、用途与当前用户启用状态。网关在设置可信上下文前检查规范正安全整数身份及access用途，refresh不能变成访问身份；公开刷新仅匹配精确路径。登录接口401由登录页处理，不触发通用401重定向丢失输入。
